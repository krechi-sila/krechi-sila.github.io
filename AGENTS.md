# Правила для агентов

Этот файл читают ИИ-агенты (Codex, Claude Code и другие), которые ведут
репозиторий: разбирают архивные материалы о Кречевицах и добавляют их на сайт.
`CLAUDE.md` ссылается сюда. Если правило меняется, правьте этот файл.

## О сайте

«Кречевицы в сети» (https://krechi-sila.github.io/) — сайт о посёлке Кречевицы
под Великим Новгородом. Он работает с 2003 года. Его читают жители, выходцы из
Кречевиц и их семьи, а также краеведы. Читатели знают места и людей лично и
заметят ошибку. Точность здесь важнее объёма и красивых формулировок.

Язык сайта и всех материалов — русский. Описания PR и issue тоже пишите
по-русски.

## Структура

Репозиторий состоит из двух независимых частей.

**Старые страницы на Next.js 13 (pages router).** Они собираются в статический
сайт и публикуются в GitHub Pages.

- `pages/` — маршруты: `/`, `/geo`, `/photos`, `/memories`, `/people`, `/airfield`.
- `components/`, `layouts/`, `lib/`, `styles/` — компоненты, шаблоны страниц,
  разбор Markdown.
- `data/` — содержимое в Markdown с frontmatter: `memories/`, `people/`,
  `airfield/`, `pages/`.

**Летопись «Кречевицы сквозь века».** Это самостоятельный статический раздел в
`public/chronicle/`, адрес на сайте — `/chronicle/index.html`. Next.js копирует
его в `out/` без изменений. В разделе нет сборщика и npm-зависимостей: это
обычные `<script>` на чистом JavaScript.

- `data.js` — словари `SOURCES`, `ERAS`, `PERIODS`, `EVENTS`, `ARCHIVE`, `TRANSCRIPTS`.
- `expansion.js` — дополнительные главы и расшифровки (дописываются в те же структуры).
- `airfield.js` — отдельная книга об аэродроме.
- `maps.js` — точки на карте.
- `app.js` — отрисовка страниц, включая «Источники и принципы» (`#sources`).
- `style.css`, `assets/` — стили и изображения.
- `vendor/` — локальная копия Leaflet с лицензией. Не редактировать.

Главы летописи по `id`: `origins` (до 1500), `manuscript` (1500–1700),
`civil` (1700–1818), `settlement` (1818–1831), `imperial` (1831–1902),
`silver` (1902–1917), `revolution` (1917–1941), `war` (1941–1945),
`soviet` (1945–1991), `modern` (1991–2026). Отдельно идёт книга об аэродроме
(`#airfield`, 1926–2026).

`openspec/` — спецификации крупных изменений сайта. Одному архивному материалу
спецификация не нужна.

## Как обрабатывать материал архива

1. Берите issue с меткой `agent-ready`, созданный по форме «Материал архива».
   В нём указаны папка на Диске, путь в архивном репозитории, тип, эпоха,
   задача и критерии готовности.
2. Прочитайте исходник целиком. Пересказ из названия файла или чужого описания
   прочтением не считается.
3. Добавьте материал по правилам ниже. Источник заведите в `SOURCES`, а в
   записях ссылайтесь на него по ключу `source`.
4. Откройте PR в `dev` по шаблону. В нём должны быть источник, что проверено,
   что осталось спорным и скриншот.

**Один материал — один PR.** Не объединяйте несколько материалов в одном PR и
не смешивайте содержание с правками кода, стилей или зависимостей. Если
по пути нашлась ошибка в другом месте, опишите её в PR или в отдельном issue,
а не исправляйте попутно.

## Редакционные правила летописи

Эти правила взяты из раздела «Источники и принципы» (`app.js`, функция `sources`)
и из того, как оформлены текущие материалы. Если вы их меняете, обновите и
страницу «Источники и принципы».

- **Пометка «по сборнику».** Она ставится, если сведения пока приводятся по
  одному краеведческому источнику — «Кречевицкому историческому сборнику»
  (`SOURCES.history`). Автор сборника сам предупреждает о его незавершённости.
  Пометку можно снять только после подтверждения независимым источником, и
  этот источник нужно указать.
- **Даты учитываются раздельно.** Точная дата, приблизительная дата, дата
  публикации или издания и дата изображённого события — разные сведения, и
  их нельзя смешивать. Примеры из `ARCHIVE`: `XVII век · издание 1906`,
  `1500–1788 · выписка 2003`, `около 2006`. Газета 1978 года, которая ищет людей
  на фото конца 1920-х — начала 1930-х, — это две разные даты.
- **Основание даты или атрибуции указывается.** Например: «дата портрета — по
  названию файла», «атрибуция — по имени архивного файла», «номер — по помете
  на скане», «место съёмки не установлено».
- **Спорные сведения отмечаются явно**, прямо в тексте. Примеры: «требуется
  сверить», «биографии ещё проверяются», «ожидает проверки координат». Если
  источники расходятся, приводите обе версии со ссылками и не выбирайте одну
  молча. PR с такими местами получает метку `needs-fact-check`.
- **Характер связи с Кречевицами указывается отдельно.** Человек мог жить,
  служить, родиться рядом или приезжать в командировку, и это разные вещи.
  Не превращайте «был в командировке» в «жил».
- **Ничего не выдумывать.** Нельзя добавлять имена, даты, места, цитаты,
  координаты, звания или подробности, которых нет в источнике. Нельзя
  «улучшать» цитаты и заполнять пробелы правдоподобными догадками.
- **Ничего не «додатировать».** Если в источнике нет даты, пишите «дата не
  установлена». Нельзя сужать «1920-е» до конкретного года, выдавать дату
  публикации за дату события или выводить год из соседних материалов без
  явной оговорки.
- **Расшифровки передаются как есть.** Орфография и ошибки оригинала
  сохраняются, пропуски отмечаются `[…]`, неразборчивые места — `[нрзб.]`.
  Пока копия не сверена с оригиналом, над ней стоит пометка: «Копия ещё не
  сверена с печатным оригиналом; орфография и возможные ошибки сохранены».
- **Контекст страны — не источник о Кречевицах.** «Намедни» и общие справочники
  используются только для ориентира в событиях страны.
- **Послевоенные подэпохи** (`PERIODS`) — редакционная схема. Историческим
  фактом она не является.

## Авторские права и личные данные

- **Сканы книг и газет целиком не публикуем**: ни страницы, ни полосы, ни
  номера. Допустимы расшифровка фрагмента, относящегося к Кречевицам,
  описание материала, библиографическая ссылка и ссылка на источник (Диск,
  НЭБ, сайт библиотеки).
- Происхождение фотографий и документов из частных собраний указывается в
  подписи, например «Из коллекции Ю. Маркитанова».
- Воспоминания публикуются только с согласия автора. Указываются автор,
  человек или семья, период, место и источник сведений. Если согласия нет,
  материал не публикуется: в PR описываем, что нужно получить.
- О живых людях не публикуем ничего сверх того, что есть в источнике и нужно
  для истории: ни адресов, ни телефонов, ни документов.
- Если не уверены, можно ли публиковать файл, не добавляйте его. Опишите
  материал и вопрос в PR.

## Сборка и проверка

Зависимости уже зафиксированы в `pnpm-lock.yaml`. Не меняйте `package.json` и
lock-файлы, не добавляйте пакеты и не коммитьте `package-lock.json`.

```sh
pnpm install --frozen-lockfile   # только если нет node_modules

# Изменения только в летописи: сборка не нужна
node --check public/chronicle/data.js   # для каждого изменённого .js
git diff --check
python3 -m http.server 8000 --directory public
# открыть http://localhost:8000/chronicle/index.html#archive

# Изменения в Next.js-части (если PR затрагивает только летопись, собирает CI)
npm run lint
npm run build && npm run export   # результат в out/
python3 -m http.server 8000 --directory out
```

CI (`.github/workflows/build.yml`) повторяет сборку и экспорт. Публикация в
GitHub Pages идёт из ветки `dev`.

## Ограничения машины

Агенты работают на машине с **8 ГБ оперативной памяти**.

- Запускайте не больше одной сборки за раз. Не запускайте `next dev`
  параллельно с `next build` и не собирайте несколько веток одновременно.
- Не запускайте тяжёлые браузерные тесты: наборы Playwright или Cypress,
  прогоны по многим страницам, несколько браузеров сразу. Для скриншота в PR
  достаточно одного headless-снимка одной страницы. Сделав снимок, закройте
  браузер и сервер.
- Если скриншот сделать не удалось, так и напишите в PR. Не прикладывайте
  старый или чужой снимок.
- Не устанавливайте глобальные пакеты и браузеры без запроса.

## Git, issue и PR

- Ветки создавайте от `dev`, PR открывайте в `dev`. Имена веток:
  `archive/<кратко-о-материале>` для материалов и `chore/…`, `fix/…`, `feat/…`
  для остального.
- Используйте форму issue «Материал архива» и шаблон PR из `.github/`.
- Метки:
  - `archive` — работа с материалом архива;
  - `content` — изменение текстов и данных сайта;
  - `agent-ready` — задача описана полностью, агент может её брать;
  - `needs-fact-check` — в материале есть спорные или непроверенные сведения,
    нужна проверка человеком.
- Не сливайте PR сами и не пушьте напрямую в `dev`.
