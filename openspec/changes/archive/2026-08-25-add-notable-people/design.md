## Context

Сайт — статически экспортируемый Next.js (Pages Router) на GitHub Pages. Разделы «Истории» и «Аэродром» уже задают паттерн: markdown в `data/<section>/`, `getStaticPaths` / `getStaticProps`, общие `lib/getAllFilesIds` и `lib/parseMarkdownFile`, пункт в `components/Menu/Menu.jsx`. См. proposal.md — Why / What Changes.

## Goals / Non-Goals

**Goals:**
- Повторить проверенный контентный паттерн сайта для раздела людей
- Список + детальная страница без новых зависимостей
- Стартовый контент (2–3 записи), чтобы раздел сразу был осмысленным

**Non-Goals:**
- CMS, формы предложений, модерация
- Поиск, фильтры, теги, сортировка по алфавиту сверх простого списка
- Миграция на App Router / Next 16
- Отдельный дизайн-система redesign меню или layout

## Decisions

### 1. Маршрут `/people`, UI-название «Известные люди»
- **Почему:** существующие разделы используют английские path (`/memories`, `/airfield`, `/geo`, `/photos`) при русских заголовках.
- **Альтернатива:** `/izvestnye-lyudi` — длиннее, выбивается из текущих URL.

### 2. Данные в `data/people/*.md`
- **Почему:** зеркало `data/memories` и `data/airfield`; один pipeline парсинга.
- **Front matter:** обязательный `title`; опционально `years` (годы жизни / период), `role` (краткая роль), `image` (путь относительно `public/`).
- **Slug:** имя файла без `.md` (как у memories).
- **Альтернатива:** JSON/JS каталог — хуже для длинного текста биографий.

### 3. Страницы по образцу memories, список проще
- `pages/people/index.jsx` — список ссылок (имя + опционально `role` / `years`), без группировки по годам (у людей нет единого «memory_date»).
- `pages/people/[slug].jsx` — заголовок + HTML из markdown.
- Переиспользовать `PagesLayout`, `getAllFilesIds`, `parseMarkdownFile`.
- **Альтернатива:** отдельный React-компонент `People` как `Memories` — отложить, пока список короткий; при необходимости вынести позже.

### 4. Меню
- Добавить `ActiveLink` на `/people` с текстом «Известные люди» рядом с существующими пунктами (логично после «Истории»).

### 5. Стартовый контент
- 2–3 markdown-файла с краткими справками (можно опираться на уже упомянутых в главной / историях фигур, например связанных с военными поселениями / авиаполком), с пометкой что тексты можно уточнять позже.
- Фото опциональны; если есть — в `public/images/people/`.

## Risks / Trade-offs

- **[Risk] Спорный или неполный список «известных»** → Mitigation: стартовый набор небольшой; контент правится как обычные файлы в репо; не претендовать на исчерпывающий каталог.
- **[Risk] Дублирование биографий с «Историями»** → Mitigation: в people — портрет человека; в memories — события. Допустимы перекрёстные ссылки в markdown.
- **[Trade-off] Простой список без группировки** → проще и достаточнее для малого N; при росте каталога можно добавить алфавитную сортировку без смены контракта URL.

## Migration Plan

1. Добавить данные и страницы, пункт меню.
2. `next build` / export как обычно; GitHub Pages подхватит новые HTML.
3. Rollback: удалить пункт меню и каталоги `pages/people`, `data/people` (и опциональные картинки).
